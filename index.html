ESP32 — live link protocol v0.1 · firmware in tools/esp32/

Web Serial needs Chrome or Edge, on localhost or HTTPS. The firmware (tools/esp32/main.py) plays the digit's pulse train — one wired pin streams the 64 pixels serially, or 8 pins in parallel — and streams each digit's state back over USB serial. With no WS₂ sample wired, that state comes from the device's on-board model — the same equations as the Playground — so the full send → pulse → state → train loop still runs.

Protocol v0.1 (line based, USB serial)

host → device : S <id> <64 hex chars>    level per pixel 0…F, row-major
                1 pin: 64 serial slots · 8 pins: slot t = column t
                C <key> <value>       pulse + reservoir config (C chans 4 …)
                C status | C ping     config dump / liveness
device → host : R <id> <n> <f0> <f1>…  state: 8 readouts × 2n floats
                K <text>              log / ack

Full key list and flashing steps: tools/esp32/README.md. Software model and hardware share this state interface, so the Playground visualisations apply to device replies too.

The classic plan avoids strapping pins (0, 2, 12, 15) and flash pins (6–11). The ESP32-C3 has no GPIO 11–17 and uses 18/19 for USB, so the firmware ships the C3 remap above; change it live with C chans 4,5,6,7,10,20,21,3. Pulses are plain GPIO + shifters on every chip — no DAC involved.

How a run works

  1. The browser sends one digit as 64 pulse levels (one nibble per pixel) over USB serial.
  2. The firmware plays the pattern: with 8 pins as parallel pulse trains (slot j = column j); with one pin the 64 pixels stream one per slot, row-major. The bench free-run pulse parks meanwhile.
  3. Every few slots the state is read out — via the TIA/ADC with a wired sample; with none, from the on-device model (the Playground's equations). 8 readouts → one state vector (16n floats).
  4. States stream back to the browser, which trains the readout and reports accuracy on a train/test split of the collected states.
  5. Repeat for the next digit. The same loop powers the paper-style experiments: 4-bit pattern separability, STP/LTP·PPF plasticity, noise robustness.
